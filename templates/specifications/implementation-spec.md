# Implementation specification template

Use only the sections that materially apply. This template guides the Specification Architect; it
is not unconditional target output.

```markdown
# <ID> — <Outcome>

## Metadata

- ID, status, parent/dependencies, explicit supersession relationships, and approval evidence

## Problem and desired outcome

## Scope and non-goals

## Current and required behavior

## Decisions, assumptions, risks, and open questions

Keep confirmed facts, inferences, accepted decisions, reversible assumptions, rejected options, and
open questions distinct. Record sensitive decisions only after explicit confirmation.

## Structure, implementation sequence, and failure/recovery

Include only when structure, sequencing, capabilities, migration, or recovery materially affects
the outcome.

## Acceptance criteria

Describe observable starting state, action, and result.

## Verification

Map each important criterion to practical automated or manual evidence.

## Documentation impact

## Completion evidence
```

Do not add empty security, API, data, migration, accessibility, or operational sections when they
are irrelevant. Sensitive or irreversible decisions require explicit confirmation.
